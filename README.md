# SteamRip → Steam Buttons

A small browser extension that adds quick-link buttons to game pages on SteamRip. It finds the matching game on Steam and shows buttons for the Steam Store, reviews, community hub, SteamDB, and PCGamingWiki.

> 🤖 **Made with Claude AI.** This extension was written by [Claude](https://claude.ai), an AI assistant made by Anthropic, from prompts by the repository owner. Review the code before using it.

## Features

- Detects SteamRip game pages automatically (URLs ending in `-free-download`)
- Cleans the page title (removes "Free Download", version numbers, tags) and searches Steam for the best match
- Shows the game's capsule image, App ID, and price
- Buttons for:
  - 🛒 Steam Store
  - ⭐ Reviews
  - 💬 Community Hub
  - 📊 SteamDB
  - 🛠️ PCGamingWiki
  - 🔍 Manual "Wrong game? Search" fallback
- **Opens in the Steam app first**, and falls back to the browser if Steam isn't available
- Ctrl / Shift / Middle-click opens the normal web link in a new tab

## Installation (Chrome / Edge / Brave)

1. Download or clone this repository
2. Open `chrome://extensions`
3. Enable **Developer mode**
4. Click **Load unpacked** and select the project folder
5. Open any game page on SteamRip

> The first time you click a button, your browser may ask to open Steam. Tick **"Always allow"** so it doesn't ask again.

## How it works

1. `content.js` runs on SteamRip game pages and reads the game title.
2. It sends several cleaned-up title variations to `background.js`.
3. `background.js` queries Steam's public store search API (content scripts can't due to CORS).
4. The best match is picked by word overlap, and the buttons are injected under the title.
5. On click, the extension tries a `steam://` link. If the page doesn't lose focus within about 1.5 seconds, it opens the web URL instead.

## Limitations

- Bundles and collections may match the wrong Steam listing. Use the "Wrong game? Search" button.
- Detecting whether the Steam app is installed is a heuristic. Browsers don't expose this directly.
- Firefox needs a small manifest change (`background.scripts` instead of `service_worker`).
